# 3 分钟演示视频分镜脚本

总时长约 180 s。以下按计划书第九章的六个时段组织；若计划书原文对六段有固定标题，只需把“时段”标题替换，画面和解说保持不变。

| 时段 | 时间 | 画面 | 解说词 |
|---|---:|---|---|
| 1. 系统与上电 | 0～25 s | 全景拍摄核心板、扩展板、OLED、传感器；特写上电日志 `JEDEC=0xEF4017`、KV 就绪、任务水位 | “这是基于 STM32F103C8T6 和 FreeRTOS 的智能环境监测与安防联动系统。上电先完成 OLED、传感器、W25Q64 和 ESP8266 自检，执行器默认保持安全态。” |
| 2. 传感采集 | 25～60 s | OLED 主页和串口 telemetry；手持目标改变距离，展示 DHT11 温湿度、超声距离、Rd-03 人体状态、MQ 预热状态 | “DataHub 对所有传感器统一提供值、质量和时间戳。任务只读快照，通信超时或数据过期会进入故障质量，不会用旧值继续联动。” |
| 3. 本地菜单 | 60～85 s | PA0 单击/长按切换 Manual Test，PB15 确认，PC13 返回；演示风扇滑杆、舵机角度和距离显示 | “本地界面不依赖网络。PA0 单击下一项、长按上一项，PB15 确认，PC13 返回。手动执行器只在撤防且健康时开放。” |
| 4. 报警联动 | 85～125 s | 用安全夹具触发双鉴或模拟 MQ DO；拍摄 OLED/ RGB、风扇、舵机和串口 event；随后解除条件 | “报警引擎按严格状态机运行：自检、故障、撤防、预热、布防到报警。火灾优先级最高，联动红闪、风扇和舵机；入侵要求雷达有人且距离小于阈值，解除持续十秒自动恢复。” |
| 5. MQTT 与云看板 | 125～160 s | PC 看板显示曲线和状态；MQTTX 订阅 `smshub/<dev>/#`，发送 `fan=45`、`servo=90`、`arm=0` 并展示 `queued→done` | “网络侧使用现有 ESP AT 固件，STM32 通过 TCP 承载 MQTT。看板订阅 telemetry、event、status 和 config，命令必须等待最终回执，不把 publish 成功误认为设备动作成功。” |
| 6. 安全与交付 | 160～180 s | 展示 W25Q64 接线、PA4/PA7 波形截图占位、README、测试报告和资源页；最后定格资源数字 | “Flash KV 采用双 Bank、提交标记和读回校验；SPI 与风扇共享引脚由仲裁器切换。当前生产镜像 Flash 61416 字节、RAM 20256 字节，硬件证据和二十四小时烤机按报告逐项归档。” |

## 拍摄要求

- 串口窗口字体至少 14 pt，日志从冷启动开始，不裁掉 BOOT、KV、传感器和网络行。
- 报警动作使用隔离电平夹具或低风险测试条件，禁止明火、烟雾和机械夹伤。
- 看板录制同时显示设备 dev、topic 和回执；不要在画面中出现真实 WiFi 密码。
- 片尾展示 `Docs/test_report.md` 中的实际结论，未测项目保留“待板测”，不剪辑成已通过。
