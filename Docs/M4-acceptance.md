## 2026-10-11 Flash KV 启动修复

启动日志的 `KV扫描结果=-1 序号=2` 与扫描发现合法记录后 SPI 读失败一致。现有低优先级 LogTask 的 HAL polling 接收以墙钟计算 10ms 超时，可被更高优先级 OLED/同步 UART 抢占超过该窗口。实际 KV/W25Q/仲裁器件模型在 Bank B 第二槽接收时注入 40ms 抢占，旧驱动复现 `-1/seq2`，修复后扫描成功且保留 seq2。

修复仅在单次 HAL SPI 发送/接收内暂停任务切换；中断及 TIM4 毫秒时基保持运行，BUSY 轮询仍每 2ms 让出任务。原有 SPI 超时、擦写上限、页边界、CRC、commit 和错误后离线保留不变，不增加堆对象、不擦除现场介质。正常 256B 的线速约 0.228ms，真实硬件故障时这一调度窗口可持续至原 10ms SPI 超时，需复测任务时序。

本轮验证：抢占回归、注入真实 HAL 超时的模型、500次保存与逐字节掉电恢复、OLED/菜单/传感器回归均通过；Keil V6.24 全量构建 0错误0警告。当前映像 Flash=54092B（包含112B RW初始化数据），RAM=19464B，均在60KB/20KB预算内。当前普通 HEX 为 `MDK-ARM/Objects/sms-hub.hex`，SHA256=`10558D9AD6800A51F0201E04148A83B76551C742DEBDEDF77924FEA82495064E`；构建及 map 单独保存为 `Docs/M4-kv-fix-build.log`/`Docs/M4-kv-fix-map.txt`，未覆盖先前 M4 记录。

未进行实物下载或掉电验收。先按下方接线检查烧录新 HEX，应出现“存储就绪”；再改温度51、等待“配置已保存”，复位检查51仍在。若新版本仍失败，应记录具体失败地址/HAL状态并检查供电与共享总线；不能仅凭本机模型排除现场电气问题。

## 最终布局与格式
此次沿用已确认的物理4KB扇区隔离，M4提示中的“各2KB”不再按同扇区旧方案实现。完整WiFi/MQTT配置无法放入旧128B记录，因此改512B定长槽；每个Bank8槽，不是32槽。

| 区域 | 地址范围 | 格式 |
|---|---|---|
| KV A | 0x000000~0x000FFF | 4KB独立扇区，8×512B |
| KV B | 0x001000~0x001FFF | 4KB独立扇区，8×512B |
| 预留 | 0x002000~0x002FFF | 本实现不读写 |
| 事件环 | 0x003000~0x012FFF | 16×4KB，32B/条，共2048物理槽 |

config_t固定512B，包含magic/version/seq、温度×10/距离/烟雾/空气/入侵确认/解除/遥测周期、模式、MQTT端口/keepalive、SSID/密码、MQTT主机/用户名/密码、device、保留零字节、CRC32、commit。字符串容量33/65/65/33/65/33字节，包含结尾零；默认字符串过长会编译失败。字段范围和版本经过验证。
介质采用当前STM32/主机一致的小端定长结构，版本1，编译断言验证大小及commit偏移。未来结构变更要升版本并设计迁移，不能直接重解释旧字节。
CRC32为标准反射CRC32，测试串123456789得到0xCBF43926；提交标记0x434F4D54在最后单独编程。记录只有在magic/版本/字段/CRC/commit全部正确时才有效。

## 文件与行为
- BSP/bus_arbiter.h/.c：现有SPI1共享引脚mutex，take配置PA4GPIO-CS、PA5/PA7 AF推挽、PA6输入；give先STBY=0，再禁SPI、PA5/PA7=0、风扇CCR4=0。禁止ISR/临界区/故障态take，拥有者才可give；保留NOJTAG。
- Drivers_Device/w25q64：模式0、9MHz由M0 SPI初始化复用。read/init/program/erase全部经过仲裁；JEDEC不匹配则禁用写入，不进入反复复位。检查WEL、WIP，页编程禁止跨页并要求擦空、逐块读回验证；扇区擦除后读回全扇区检查。SPI接收dummy明确发送0xFF。没有删除超时或校验来强行成功。
- 擦除典型45ms只是参考；软件上限600ms、页编程20ms、初次忙状态800ms。轮询每2ms vTaskDelay，不阻塞其它任务；只由Monitor按原心跳表喂狗。600ms低于标称4s看门狗且低于1s业务心跳窗口，但完整API时长受调度影响，需实板高水位/心跳复测，不能用典型45ms替代实测。
- Drivers_Device/kvstore：每次提交在与最新有效记录相反的Bank顺序追加，满了才擦该目标Bank，另一扇区保留最新值。正常重启扫描16槽选最新；seq回绕用有界序列比较。新/第一次写入中断的介质在空槽初始化两份默认值；若任一Bank无尾部空槽且无有效记录，则保留现场并报错，不自动抹掉未知数据。
- Drivers_Device/eventlog：按物理槽前进，跳过不完整编程槽；下一扇区首次使用前擦除，禁止擦含最新有效记录的扇区。启动扫描2048槽重建头部位置/序号，读取时由最新向前遍历；**没有额外高频头尾指针扇区**，从CRC有效数据重建，避免元数据扇区先磨损。覆盖按16扇区轮转。log_read_last(n)返回最新在前，跳过CRC/提交失败记录。
- App/storage：LogTask是唯一Flash/KV/log写者，4条有界请求队列，缓存最近20条供菜单读取；缓存/字段读锁只包围内存复制，硬件访问不在UI锁内。队列满/离线/上次配置未完成会返回错误，丢弃计数可诊断，不能静默说已保存。
- 菜单：PB15进入编辑，PA0短按增/长按减，PB15再次确认排队保存；PC13直接返回取消未提交编辑。只有KV提交+读回成功才同步RAM字段与DataHub气体确认时长。Arm页面切换模式也通过KV。Flash失败显示STORE OFFLINE，不伪装保存成功。
- Event Log：PA0单击下一条、长按上一条，最多20条、5行滚动，PB15/PC13原导航不变；显示序号/类型/参数，底行Unix时间和第二参数。类型1=启动、2=配置提交、3=手动测试。每次启动追加启动事件，序号不会从1重新开始。
- System：`Erase boot`是本次启动成功擦除总次数，复位清零；`E`是本次存储错误。**没有实现全寿命掉电持久化擦除计数**，不能将该值宣称为累计寿命磨损数据。

## 基本串口预期
以下是格式示例，不是实物记录：
```
[<tick>][日志任务][信息] Flash JEDEC=0xEF4017 SPI=9MHz
[<tick>][日志任务][信息] 存储就绪 KV序号=<n> 最近事件=<n> 擦除=<n>
[<tick>][日志任务][信息] 配置已保存 序号=<n> 字段=0 值=51
```
字段0温度℃、1距离cm、2烟雾确认ms、3空气确认ms、4布防模式。密码不会打印到串口。
ID为0/FFFFFF/其它值时检查供电/跳帽/接触和方向，禁止跳过身份断言。存储故障后保留上一已确认UI/DataHub值，停止所有新写入，复位重新扫描；如果提交其实已落盘但应答/读回失败，重启可能读到新值，这是结果未知场景的正常保守处理。
