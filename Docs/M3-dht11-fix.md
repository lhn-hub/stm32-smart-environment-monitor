## 缺陷与修复

旧驱动在低脉冲结束后调用HAL配置上拉输入/双沿EXTI。当前F1 HAL先写ODR高释放总线，之后才更新GPIO、AFIO、触发器和IMR；驱动随后清PR，可能丢掉早响应下降沿。不是“忘记拉高”。

新驱动在初始化时配置PB12/双沿EXTI并屏蔽IMR；每次仍用开漏拉低，再在短临界区准备捕获、清旧PR、开启IMR、记录时间、显式ODR置高释放。接收期间不重配EXTI或清PR，结束后关闭DHT接收并恢复上拉输入。

82段完整性、脉宽范围、40bit累加校验、数据范围、7ms捕获截止、失败质量和看门狗均保留。没有整帧关中断、增加堆对象、修改TIM4时基或此前Flash驱动修复。

主机模型中13us响应/零配置延迟可以正常解码；旧驱动遇到10us响应及注入16us配置延迟时只收81段，返回INCOMPLETE；修复后通过。16us为故障注入，未实测板上配置耗时。现场最新日志是NO_RESPONSE/0段，此模型没有复现它，不能把软件缺陷认定为唯一现场原因。

## 烧录与观察

1. 使用`MDK-ARM/Objects/sms-hub.hex`烧录当前普通固件；构建记录为`M3-dht-fix-build.log`，0错误0警告。
2. 完全断电后检查模块正向接在IO3、3V3/GND/DATA对应，再重新上电。日志每5秒输出DHT统计，不需要反复复位。
3. 运行约2分钟，检查DHT成功计数、有效温湿度及时间戳是否增加。连续50次尝试至少48次成功才达到原≥95%要求，温湿度精度需另与参考仪表对比。
4. 若仍无响应，提供新日志的“采集统计”“DHT诊断”“DHT失败数”，用以下字段继续定位。

新诊断格式：

```text
DHT诊断 最近失败=<码> 拉低=<ms> 采集=<us> 段=<数> 异常段=<索引>/<us> 电平=<起始低末端>/<刚释放>/<捕获结束> IRQ=<接收回调数>
```

电平0/1为实际GPIO读数，2表示该阶段未执行。IRQ计数包括主机释放产生的上升沿，不等同于传感器响应数。诊断保留最近失败，即使后续成功也不清零；是否恢复看成功计数与时间戳。

| 最近失败为NO_RESPONSE时的观测 | 下一步 |
|---|---|
| 电平0/1/1，IRQ=1 | 起始低与释放高已读到，但未捕获传感器响应；核对供电、DATA连接、模块方向及上拉 |
| 电平0/0/0，IRQ=0 | 数据线到捕获结束仍低；测量DATA与3V3、排查持续拉低或上拉/连接问题 |
| 电平0/1/1，IRQ=0 | 读到释放高但无回调；进一步核查实际烧录版本、EXTI/AFIO/NVIC及PR，不直接判断模块坏 |
| 起始低末端为1 | 检查PB12是否真正拉低、连接或电气争用 |

“刚释放”是瞬时采样，RC上升或抢占可能影响读数，单独一个0不能证明短路；需结合结束电平、IRQ与真实波形。
