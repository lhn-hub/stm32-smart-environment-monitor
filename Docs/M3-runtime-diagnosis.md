### OLED最小修订
复用现有console priority-inheritance互斥锁，每个I2C命令/32B数据块前短暂取得，传输结束立即释放。更高优先级日志等待时通过优先级继承让该块完成；没有新建锁、改6任务优先级、屏蔽中断、暂停调度或增大8ms传输超时。
取得console锁的等待仍有APP_LOG_LOCK_MS=50ms上限；等不到时返回OLED_DEFERRED(-2)，保留脏页，不清空屏幕、不误判掉线、不计为成功帧；下个帧周期从页首重发。console锁不是I2C多客户端互斥，不改变原单任务I2C所有权；锁内不能调用LOG/printf。
此修改避免了同步日志进入块内的可重现模型风险，物理总线问题仍可能存在。GPIO、采集参数、MQ禁用与看门狗保护全部保留。

## 烧录后需要的输出
复位运行约30秒，提供一组“采集统计”“DHT诊断”“DHT失败数”“超声诊断”“OLED诊断”。无需填写标定表。
各驱动“最近失败”会保留到下一次失败，即使下一帧已成功也不清空；这是刻意保留故障证据，不代表该时刻仍失败。

### DHT
`DHT诊断 最近失败=<码> 拉低=<ms> 采集=<us> 段=<个数> 异常段=<索引>/<us>`
`DHT失败数 拉低超时=... 无响应=... 缺段=... 边沿=... 响应宽=... 位宽=... 校验=... 范围=...`

| 码 | 解释 |
|---|---|
| 0 | 没有记录失败 |
| 1 | 起始低电平超过30ms，需排查任务调度延迟 |
| 2 | 没有收到响应起始下降沿 |
| 3 | 接收宽度段不足82段 |
| 4 | 相邻捕获边沿间隔超过200us |
| 5 | 响应低/高宽度不在既定范围 |
| 6 | 数据位低/高宽度异常，索引与宽度可用于追查丢沿/延迟 |
| 7 | 40bit收齐但校验和错误 |
| 8 | 温湿度范围/小数编码不合法 |

脉宽异常不能直接证明传感器坏；软件观测时间包含中断响应延迟。取得分类证据后再决定最小修复，不直接放宽脉宽判定。

### 超声
`超声诊断 最近失败=<码> 等待=<us> 脉宽=<us> 上升=<累计> 下降=<累计> ECHO=<当前电平>`

| 码 | 解释 |
|---|---|
| 0 | 没有记录失败 |
| 1 | 触发前ECHO已高，本次未触发 |
| 2 | 短触发延时返回错误 |
| 3 | 30ms内没有有效上升沿 |
| 4 | 有上升沿但没有下降沿 |
| 5 | 完成回波已超过30ms截止时间 |
| 6 | 回波宽度不在既定范围 |

上升/下降是PA15回调累计数，ECHO是打印时电平，不能当作示波器波形。接口资料已核对扩展板第14页GND/B3/A15/3V3，仍按原PB3触发/PA15回波处理，不擅自交换引脚。

### OLED
`OLED诊断 最近状态=<HAL状态> 错误码=<位图> 失败传输=<us>`
HAL状态1=ERROR、2=BUSY、3=TIMEOUT；错误位图0x04=AF（应答失败），其余以当前HAL头文件为准。记录的是最近失败的一次命令/数据块传输耗时，成功后不抹掉。恢复失败但没有新I2C传输时，仍为上次传输记录。
保持每次传输8ms上限和500ms重试，不通过扩大超时掩盖总线问题。
